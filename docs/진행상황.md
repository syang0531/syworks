## 1. 빌드 & 실행

```powershell
.\gradlew.bat compileJava   # 컴파일
.\gradlew.bat runData       # 모델·en_us·레시피 생성 → src/generated/resources
.\gradlew.bat runClient     # 개발용 클라이언트
.\gradlew.bat runServer     # 데디케이티드 서버 (run/eula.txt 이미 있음)
.\gradlew.bat build         # build/libs/syworks-<ver>.jar
powershell -ExecutionPolicy Bypass -File tools\gen_block_textures.ps1   # 기계 블록 텍스처
powershell -ExecutionPolicy Bypass -File tools\gen_logo.ps1             # CurseForge 로고
```

**Gradle 데몬이 꺼져 있다.** `runServer`/`runClient`는 계속 떠 있으니 로그를 읽고 따로 죽여야 한다.

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'java.exe' -and $_.CommandLine -like '*Projects\syworks*' } | Stop-Process -Force
```

### 숯가마 (`c37e4f0`)

**화로가 거부하는 나무 제품을 받고, 무엇을 넣든 통나무 환산값의 2배를 준다.**

| 입력 | 개수 | 산출 |
|---|:--:|---|
| `#syworks:charrable/log` (바닐라 `#minecraft:logs_that_burn` 중첩 + **선반 9종**) | 1 | 숯 **2** |
| `#syworks:charrable/plank` (판자·계단·울타리·문·다락문·표지판·압력판, 72종) | **2** | 숯 1 |
| `#syworks:charrable/small` (슬래브·버튼·막대기·사다리·그릇, 21종) | **4** | 숯 1 |

바닐라 태그가 **크림슨·뒤틀린(균류)과 대나무(풀)를 이미 제외**한다. **걸이 표지판은 손으로 뺐다** — 사슬(철)이 들어 있다.
제작: **벽돌 8 + 화로**. 분쇄기가 응회암에서 점토를 만들어 주니 자연스럽게 이어진다.

> **선반은 1.0.0에서 들어갔다.** 26.2 신규 블록인데 0.4.0이 통째로 놓쳤다.
> **벗긴 통나무 6 → 선반 6**이라 선반 1개가 통나무 1개 값이므로 판자 등급이 아니라 **통나무 등급**이다.
> 그래서 `charrable/log`라는 중첩 태그가 생겼고, `charring_log.json`이 바닐라 태그 대신 이걸 본다.

### 광석 화덕 — 추출로를 갈아치웠다 (1.0.0에서 이름만 다시 바꿨다)

> **1.0.0에서 표시명이 배소로 → 광석 화덕이 됐다.** `ko_kr.json` 한 줄이고,
> **블록 id `ore_roaster`와 영문명 Ore Roaster는 그대로**라 월드·레시피·데이터팩에 영향이 없다.
> 배소(焙燒)가 실제 야금 용어이긴 해도 읽을 수 없으면 이름 구실을 못 한다는 판단이다.

블록 id `extraction_furnace` → **`ore_roaster`**, 레시피 타입 `extraction` → `roasting`.
**섬손으로 캔 광석 블록만 받는다.** 판별 코드는 필요 없다 — 섬손 광석은 `minecraft:iron_ore`,

> 잡석에서 철이 나오지 않게 됐으니 절반이 사라졌다. 일관성이 낫다고 판단했다. 튜닝 지점으로는 남겨 둔다.

### 검토했다가 넣지 않은 것 (1.0.0)

다시 제안하기 전에 이유부터 읽을 것. 전부 **모드가 스스로 정한 규칙**에 걸린 것들이다.

| 후보 | 왜 안 넣었나 |
|---|---|
| 석영 블록 계열 | 석영이 산출물이 된다 — §2 금지선 |
| 프리즈머린 | 조각이 가디언 드롭이라 농장 산출물이 된다 |
| 발광석 · 자수정 · 마그마 블록 | 각각 양조 재료 · 진행 재료 · 마그마 크림 |
| **콘크리트** | **복제**: 블록 하나에 모래 0.5 + 자갈 0.5라 뭘 주든 2배가 된다 |
| **뾰족한 점적석** | **복제**: 점적석 블록 1 → 뾰족한 것 4인데 블록이 이미 뼛가루 1을 준다 (4배) |
| 유리 → 모래 | 1:1이라 안전하지만, 맨손으로 캐면 아무것도 안 남아서 가치가 거의 0 |
| 진흙(mud) → 점토 | 바닐라의 "진흙 + 뾰족한 점적석" 레시피를 뺏는다 |
| 엔드석 · 퍼푸르 | 엔드는 범위 밖 (0.4.0의 결정 유지) |
| 뼈 블록 | 바닐라에 이미 뼈 블록 → 뼛가루 9가 있다 |
| 벌레 먹은 돌 계열 | 안전하긴 한데(섬손 전용, 1:1) 가치가 거의 없다 |
| **암석 → 돌 → 자갈 체인** | 심층암·네더랙 → 돌이 말이 안 되고, 얻는 것(흔해빠진 돌)보다 잃는 것(연료·시간 2배, 규칙 한 줄)이 크다 |
| **거친 흙 → 흙 → 모래 체인** | 바닐라가 **괭이 우클릭으로 공짜·즉시** 해 준다. "바닐라의 일을 빼앗지 않는다"에 걸린다 |
| 분쇄기 GUI를 양조기꼴로 | 불꽃은 가열이 아니라 **남은 연료**다(화로 GUI와 같다). 19세기 쇄석기도 석탄 동력이었다. 양조기 텍스처를 그대로 쓰면 빈 물약 슬롯 2개가 남고 화살표 위치(x=97)가 가운데가 아니다 |

### 확인된 것

`runClient` 부팅 + 월드 진입까지 **syworks 경고·오류 0**, 누락 모델/텍스처 0,
**`can't be placed` 경고도 0**(그래서 `PlacementInfo.create(input)`으로 둬도 된다).

**GUI도 유저가 직접 확인했다 (2026-09-21) — 문제 없음.** 진행 화살표·불꽃 렌더,
출력 슬롯에서 꺼낼 때 경험치가 튀는 것까지. 이제 눈으로 안 본 것은 없다.

> **Gradle이 실행한 클라이언트/서버 창은 클로드가 조작할 수 없다.** 설치된 앱이 아니라
> Gradle이 띄운 java 프로세스라 computer-use 대상이 안 되고, `runServer`도 stdin을 안 받는다
> (파이프로 `stop`을 넣어 봤지만 도착하지 않았다). 인게임 확인은 사람이 하거나 **임시 하네스**를 쓴다.
> 26.2의 GameTest는 데이터 주도(`GameTestInstance` 레지스트리)로 바뀌어서 가볍게 쓸 물건이 아니다.

## 5. 이 코드베이스의 함정 (다음 세션 필독)

### 26.2 / NeoForge 26.2 API

- **레시피 결과는 `ItemStackTemplate`** — `ItemStack.CODEC`을 쓰면 레시피 로드 시
  `Item … does not have components yet`로 터진다.
- **Ingredient JSON은 그냥 문자열**(`"minecraft:granite"`). NeoForge `SizedIngredient`는
  **`FLAT_CODEC`**(`{"ingredient":…,"count":N}`)을 써야 한다 — `NESTED_CODEC`은 형식이 다르다.
- **`RecipeSerializer`는 record**(codec, streamCodec).
- **기계 레시피는 `isSpecial()` + `PlacementInfo.NOT_PLACEABLE`** — 아니면 클라이언트가
  레시피마다 "can't be placed" 로그를 뱉는다.
- **BlockEntity는 `ItemStacksResourceHandler`**(transfer API) + `ResourceHandlerSlot`,
  드랍은 `preRemoveSideEffects`, 저장은 `ValueInput`/`ValueOutput`.
- **GUI 텍스트 색은 ARGB**(`0xFFFFFFFF`). `GuiGraphicsExtractor`/`extractBackground`/`RenderPipelines.GUI_TEXTURED`.
- **datagen은 전부 `GatherDataEvent.Client`** — 별도 서버 런이 없다.
- **화로 불꽃·화살표는 `furnace.png`에 없다.** 스프라이트로 분리됐다:
  `minecraft:container/furnace/{lit_progress,burn_progress}`. `blitSprite(...)`로 그린다.
- **tick 진행도 3분기** — (불O+처리O→진행), (불O+처리X→즉시 0), (불X+진행>0→서서히 감소).
  바닐라 화로와 같게.
- **26.2는 색깔 변형 16종을 `ColorCollection` 하나로 묶었다.** `Items.WHITE_TERRACOTTA`는
  **존재하지 않는다** — `Items.DYED_TERRACOTTA.asList()`, `Items.GLAZED_TERRACOTTA.asList()`로 받는다.
  양털·카펫·콘크리트·색유리도 같다. 1.21.x 예제를 그대로 베끼면 여기서 터진다.
- **`Items.CUT_STANDSTONE_SLAB`는 오타가 아니라 바닐라 필드명이다** (S-T-A-ndstone).
  Mojang 쪽 오타인데 그대로 써야 한다. 붉은 쪽은 `CUT_RED_SANDSTONE_SLAB`로 정상이다.
- **바닐라 `#minecraft:logs_that_burn`에 선반(shelf)은 없다.** 26.2가 추가한 목제 블록인데
  통나무 태그에도 판자 태그에도 안 들어간다 — 직접 넣어야 한다.

### 이 머신

- **파일이 CRLF다.** `perl -0pi -e`로 여러 줄을 지울 땐 패턴에 `\n`이 아니라 `\R`을 쓴다.
  치환문 쪽에는 `\R`을 못 쓰니 `\r\n`을 직접 쓴다.
- **`git ls-files`는 한글 파일명을 8진수로 escape 한다.** 일괄 치환을 돌리면 `docs/기획.md` 같은
  파일이 **조용히 빠진다.** `git -c core.quotepath=false ls-files`를 쓸 것.
- **일괄 치환에 PNG를 넣지 말 것.** 실제로 로고를 한 번 깨뜨렸다(`git checkout`으로 복구).
- **일괄 개명은 과거 이력도 바꾼다.** CHANGELOG의 "Yame → SY Alchemy" 같은 문장은 손으로 되돌려야 한다.
- **`python`을 호출하지 말 것** — Windows Store 스텁이 입력을 기다리며 멈춘다. perl이나 PowerShell `System.Drawing`.
  (2026-09-22에는 heredoc으로 `python - <<'PY'`가 정상 동작했다. 그래도 먼저 perl을 시도할 것.)
- **PowerShell/Gradle 로그가 UTF-16일 수 있다.** grep 전에 `tr -d '\000'`.
- **PowerShell 도구의 작업 디렉터리가 Bash 쪽 `cd`에 따라 옮겨갈 수 있다.** `.\gradlew.bat`이
  "not recognized"로 죽으면 이것이다. `Set-Location C:\Projects\syworks;`를 앞에 붙일 것.

### ⚠ 바닐라를 조사할 땐 반드시 이 경로를 쓸 것

- **26.2 API 참조**: `build/moddev/artifacts/minecraft-patched-26.2.0.88-sources.jar`를 풀어서 grep.
  바닐라 데이터(레시피·태그 JSON)는 `minecraft-patched-26.2.0.88.jar` 안에 있다.
- **`~/.gradle/caches/neoformruntime/` 을 직접 뒤지지 말 것.** 여기엔 **여러 마인크래프트 버전이
  섞여 있다**(26.2와 26.3이 나란히 있다). 2026-09-22에 실제로 26.3대 jar를 잡는 바람에
  존재하지 않는 아이템 32개로 코드를 쓰고 컴파일에서 터졌고, 하마터면 **황·진사·선반을 통째로 놓칠 뻔했다.**
  위의 `build/moddev/artifacts/` 경로는 **버전이 파일명에 박혀 있어서** 이런 일이 안 난다.
- 아이템 id 전수 목록이 필요하면 데이터 jar의 `assets/minecraft/items/*.json` 파일명이 가장 정확하다.

### 태그를 늘린 뒤 반드시 볼 것

- **태그 간 중복이 0인지.** 한 아이템이 두 레시피에 걸리면 어느 쪽이 도는지 보장이 없다.
  ```bash
  cd src/generated/resources/data/syworks/tags/item
  for f in crushable/*.json; do grep -oE '"minecraft:[a-z_0-9]+"' "$f"; done | sort | uniq -d
  ```
- **석재 절단기 배수.** 통짜 블록은 거의 1:1인데 **슬래브만 1 → 2**다. 울타리처럼
  다른 배수를 쓰는 것이 섞여 있으면(네더 벽돌 울타리: 블록 4 + 벽돌 2 → 6) 1:1이 곧 복제가 된다.
- `runServer`의 `Loaded N recipes`가 기대한 만큼 늘었는지.
